## Overview

Rename the LyricForge project to **noise.sh** to align with the Puente Labs Creative Shell Suite branding. This is a comprehensive renaming that affects code, documentation, configuration, and the GitHub repository.

---

## Objectives

1. ✅ Rename all references from "LyricForge" to "noise.sh" or "Noise"
2. ✅ Update binary names, package names, and command names
3. ✅ Maintain backward compatibility where possible
4. ✅ Update all documentation and README files
5. ✅ Rename GitHub repository
6. ✅ Ensure all tests still pass after renaming

## Naming Conventions

### Use These Names:

| Context | Name to Use | Example |
|---------|-------------|---------|
| **Binary/Executable** | `noise` | `./noise`, `go build -o noise` |
| **Go Module** | `github.com/youruser/noise` | `module github.com/youruser/noise` |
| **Package Name** | `noise` | `package noise` |
| **CLI Commands** | `noise [command]` | `noise new song`, `noise brainstorm` |
| **User-Facing** | "noise.sh" or "Noise" | "Welcome to noise.sh!" |
| **Variables** | `noise` or `noiseSomething` | `noiseConfig`, `noiseVersion` |
| **File Extension** | `.noise` (if needed) | `song.noise` |

### Avoid These:
- ❌ "LyricForge" - old name
- ❌ "lyricforge" - old name lowercase
- ❌ "lf" - old abbreviation

## Step-by-Step Implementation

### 🤖 For AI Agents: Quick Command Reference

**Complete rename in order:**
```bash
# 1. Rename GitHub repository (requires gh CLI)
CURRENT_REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)
OWNER=$(echo $CURRENT_REPO | cut -d'/' -f1)
OLD_NAME=$(echo $CURRENT_REPO | cut -d'/' -f2)
gh api --method PATCH "/repos/$OWNER/$OLD_NAME" -f name="noise"
git remote set-url origin "git@github.com:$OWNER/noise.git"

# 2. Create working branch
git checkout -b refactor/rename-to-noise

# 3. Update go.mod
sed -i.bak 's|github.com/[^/]*/[^/]*|github.com/'$OWNER'/noise|g' go.mod
go mod tidy

# 4. Update all Go imports (run from project root)
find . -type f -name "*.go" -exec sed -i.bak "s|github.com/$OWNER/$OLD_NAME|github.com/$OWNER/noise|g" {} \;

# 5. Update binary names in Makefile/build scripts
sed -i.bak 's/lyricforge/noise/g' Makefile

# 6. Update README and documentation
find . -name "*.md" -exec sed -i.bak 's/lyricforge/noise/g' {} \;
find . -name "*.md" -exec sed -i.bak 's/LyricForge/noise.sh/g' {} \;

# 7. Build and test
go build -o noise .
./noise --version
go test ./...

# 8. Commit changes
git add .
git commit -m "Refactor: Rename LyricForge to noise.sh"

# 9. Tag release
git tag -a v2.0.0 -m "Release 2.0.0 - Rebrand to noise.sh"
git push origin refactor/rename-to-noise
git push origin v2.0.0
```

**Note:** The detailed instructions below explain each step. Use the quick reference above for automated execution.

**AI Agent: Execute These Commands:**

```bash
# Step 1: Get current repository name
CURRENT_REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)
echo "Current repository: $CURRENT_REPO"

# Step 2: Extract owner and repo name

NEW_NAME="noise"

echo "Owner: $OWNER"
echo "Old name: $OLD_NAME"
echo "New name: $NEW_NAME"

# Step 3: Rename repository using GitHub API via gh CLI

  --method PATCH \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  "/repos/$OWNER/$OLD_NAME" \
  -f name="$NEW_NAME"

# Step 4: Update local git remote URL
git remote set-url origin "git@github.com:$OWNER/$NEW_NAME.git"

# Step 5: Verify the change

```

**Alternative Method (if gh CLI not available):**

Use curl with GitHub API:
```bash
# Get GitHub token from environment or gh CLI
GITHUB_TOKEN=$(gh auth token)

# Current repository details
OWNER="youruser"  # Replace with actual owner
OLD_NAME="lyricforge"  # Replace with actual old name
NEW_NAME="noise"

# Rename via API
curl -L \
  -X PATCH \
  -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $GITHUB_TOKEN" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  "https://api.github.com/repos/$OWNER/$OLD_NAME" \
  -d "{\"name\":\"$NEW_NAME\"}"

# Update local remote
git remote set-url origin "git@github.com:$OWNER/$NEW_NAME.git"
```

**What happens automatically:**
- ✅ GitHub redirects old URLs to new repository name
- ✅ Existing clones will continue working (GitHub handles redirects)
- ✅ Issues, PRs, and stars are preserved
- ✅ All existing URLs automatically redirect

**Verification:**
```bash
# Verify rename was successful
gh repo view

# Test that old URL redirects to new
git ls-remote "git@github.com:$OWNER/$OLD_NAME.git"
# Should show: "Repository not found" or redirect to new name
```

**If the rename fails:**
- Check authentication: `gh auth status`
- Verify you have admin permissions on the repository
- Check if the new name is already taken
- Ensure there are no typos in owner/repo names

### Quick Start: One-Command Rename (For AI Agent)

**If you want to do the GitHub rename in a single command:**

```bash
#!/bin/bash
# rename-github-repo.sh - Execute this to rename the repository

set -e  # Exit on error

echo "🔄 Starting GitHub repository rename..."

# Get current repo info
CURRENT_REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)

OLD_NAME=$(echo $CURRENT_REPO | cut -d'/' -f2)

echo "📝 Current: $OWNER/$OLD_NAME"
echo "📝 New:     $OWNER/$NEW_NAME"
read -p "Continue with rename? (y/n) " -n 1 -r
echo
if [[ ! $REPLY =~ ^[Yy]$ ]]; then
    echo "❌ Rename cancelled"
    exit 1
fi

# Rename repository
echo "🔄 Renaming repository..."
gh api \
  --method PATCH \
  -H "Accept: application/vnd.github+json" \
  "/repos/$OWNER/$OLD_NAME" \
  -f name="$NEW_NAME" \
  --silent

# Update local remote
echo "🔄 Updating local git remote..."
git remote set-url origin "git@github.com:$OWNER/$NEW_NAME.git"

# Verify
echo "✅ Repository renamed successfully!"
echo "New URL: https://github.com/$OWNER/$NEW_NAME"
git remote -v
```

## GitHub Repository Renaming - Detailed Guide

### Prerequisites for AI Agent

**Install GitHub CLI:**
```bash
# Check if already installed
gh --version

# If not installed:
# macOS: brew install gh
# Linux: See installation commands in Phase 1
# Windows: choco install gh
```

**Authenticate:**
```bash
# Login to GitHub
gh auth login

# Verify authentication
gh auth status
```

### Programmatic Renaming Steps

**Step 1: Backup Current State**
```bash
# Document current repository URL
CURRENT_REPO=$(gh repo view --json nameWithOwner -q .nameWithOwner)
echo "Current: $CURRENT_REPO" > repo_rename_backup.txt

# Get current remote
git remote -v >> repo_rename_backup.txt
```

**Step 2: Execute Rename via GitHub API**
```bash
# Extract owner and current repo name
OWNER=$(echo $CURRENT_REPO | cut -d'/' -f1)
OLD_NAME=$(echo $CURRENT_REPO | cut -d'/' -f2)
NEW_NAME="noise"

# Rename using GitHub CLI
gh api \
  --method PATCH \
  -H "Accept: application/vnd.github+json" \
  "/repos/$OWNER/$OLD_NAME" \
  -f name="$NEW_NAME" \
  --jq '.name'

# Should output: noise
```

**Step 3: Update Local Repository**
```bash
# Update git remote
git remote set-url origin "git@github.com:$OWNER/$NEW_NAME.git"

# Verify
git remote -v
```

**Step 4: Update CI/CD References**
```bash
# If you have GitHub Actions workflows
find .github/workflows -name "*.yml" -o -name "*.yaml" | while read file; do
  # Check for hardcoded repo references
  grep -l "$OWNER/$OLD_NAME" "$file" && \
  sed -i.bak "s|$OWNER/$OLD_NAME|$OWNER/$NEW_NAME|g" "$file" && \
  echo "Updated: $file"
done
```

### What GitHub Does Automatically
- ✅ Redirects `youruser/lyricforge` → `youruser/noise`
- ✅ Preserves all issues, PRs, stars, forks
- ✅ Updates clone URLs
- ✅ Old git clones continue working (via redirect)

### Verification Checklist

```bash
# 1. Verify repository renamed
gh repo view --json name,nameWithOwner

# 2. Test web URL (should redirect)
echo "Visit: https://github.com/$OWNER/$OLD_NAME"
echo "Should redirect to: https://github.com/$OWNER/$NEW_NAME"

# 3. Test git operations
git fetch origin
git pull origin main

# 4. Check that old URL redirects
git ls-remote "https://github.com/$OWNER/$OLD_NAME.git"
```

### Troubleshooting

**Error: "Not Found" or 404**
```bash
# Check authentication
gh auth status

# Re-authenticate if needed
gh auth login --web
```

**Error: "Name already exists"**
```bash
# The name 'noise' might be taken
# Try checking:
gh repo view $OWNER/noise 2>&1 | grep -q "Could not resolve" && echo "Available" || echo "Already exists"

# If taken, you'll need to choose a different name or resolve the conflict
```

**Error: "Insufficient permissions"**
```bash
# Verify you have admin rights
gh api "/repos/$OWNER/$OLD_NAME" --jq '.permissions'

# Should show: "admin": true
```
